# Форматы данных и взаимодействие этапов

Акустический протокол из общего шаблона к этой задаче не применяется. Здесь описаны файловые границы конвейера.

- `artifacts/perception/camera_new_N.parquet`: наблюдения одной камеры. `frame` — исходный номер кадра, `raw_track` — номер внутрикамерного трекера; рамка и маска используют размер 1296×972. `mask_rle` — COCO RLE. `t_s` при загрузке уточняется по текущим часам камеры.
- `*_emb.npz`, `*_emb_dense.npz`: пары `(frame, raw_track)` в `keys` и соответствующие векторы `vectors`. Для склейки используется внешность, центрированная по камере.
- `configs/clocks.yaml`: частота кадров и время нулевого кадра. Время записи считается по кадрам, не по ненадёжным временным меткам контейнера.
- `artifacts/tracks/observations.parquet`: положение на плане и назначенный треклет; `tracks.json`: итоговые ID, начало/конец, камеры, сегменты, связи и признаки уверенности.
- `results/tracks.csv`: компактный перечень ID, начала, конца и камер. Времена — показания часов предоставленной записи, не время выполнения программы.
- `render/full/manifest.json`: части мозаики, их временные границы и события. `built_from.json`: нормализованные контрольные суммы исходных таблиц, из которых собран показ.

Разметка `evaluation/fragment_truth.py` применяется после вычисления идентичностей для получения метрик. Она не является входом алгоритма ассоциации.
