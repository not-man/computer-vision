# Контекст проекта и разговора

Выжимка чата с Claude Code от 6–7 ноября 2026. Этого файла достаточно, чтобы продолжить работу в новой сессии. Подробности: `docs/STATUS.md` (состояние), `docs/SOLUTION.md` (описание решения), `docs/DESIGN.md` (проект и измерения), ТЗ и презентация в `docs/brief/`.

Новой сессии можно написать: «Прочитай docs/CONTEXT.md и docs/STATUS.md и продолжай».

## Задача и команда

- Двухдневный хакатон NtechLab по межкамерному трекингу людей. Команда **ТОКЕНЫ ЗАКОНЧИЛИСЬ**. Пользователь хочет победить.
- Правило: один ID, пока человек виден хотя бы одной камерой. Трек через несколько камер считается один раз. Треков может быть больше, чем людей.
- **Ответ организаторов на чекпоинте 7 ноября: длительное отсутствие значит больше одной минуты, если человека нет ни в одном кадре.** До этого ответа возврат всегда давал новый номер.
- Сдать (слайд 8): прототип и код; инструкцию и зависимости; демо; число и перечень треков (ID, начало, конец, камеры); описание: алгоритм, готовые компоненты, ограничения, улучшения. Из ТЗ и слайда 5 ещё: признаки и правила, пример ошибки, что написала команда.
- Оценка (слайд 9): ID при переходе, завершение трека, подсчёт, повторяемость, понятность демонстрации.
- Без ответа остаются: запрещены ли готовые модели межкамерного трекинга (ТЗ и слайд 5 расходятся, мы их не используем); запускают ли проверяющие прототип сами и на какой записи.

**Решение пользователя от 7 ноября: вернувшегося быстрее минуты узнаём по внешности, правило возврата остаётся.** Цель теперь: поднимать точность. Пользователь оформляет подписку Colab для прогонов детекции.

## План улучшений по порядку

1. Сравнить варианты внешности на CPU: вырезание фона по маске, другие модели. Сейчас порог возврата пропускает около 40% своих пар. Оставлять только то, что улучшило измеренное.
2. Контрольная разметка 5–10 минут и настоящая метрика: снимки готовит `scripts/draw_board.py`, человек сверяет. Сейчас размечена только толпа: `src/mct/fragment_truth.py`, считает `scripts/eval_fragment.py`.
3. Детекция в большем разрешении: сначала пробный прогон в Colab на окне толпы и дальнем конце cam_5, всю запись только если метрика выросла.
4. Точечные ошибки: #40, #60, #39.
5. Надёжный запуск: Windows, кодировка `read_text()`, чистая машина, доступ проверяющих к закрытому репозитории, слияние в `main`.
6. Показ: подсветка выбранного трека, клик по таймлайну, измеренное качество на экране, сценарий на 3 минуты, запись показа.

## Как работать с пользователем

- Отвечать по-русски, коротко. Сообщения пользователя бывают короткими и прямо во время работы: на них отвечать сразу.
- Текст, написанный между вызовами инструментов, пользователь может не увидеть вовремя. Срочное (например, текст для чата хакатона) лучше отдавать закрывающим сообщением.
- Детектор и ReID на всей записи запускать только в Colab, запускает пользователь (`colab/run_perception.ipynb`, около 1 ч 25 мин). Остальное считается на ноутбуке.
- По ходу работы давать список ручных проверок: что, где, когда, путь к файлу.
- Коммитить на контрольных точках, особенно когда заканчивается контекст. Автор в git не задан: `git -c user.name=not-man -c user.email=<почта из первого коммита> commit`, настройки не менять.
- В `main` сливать только по просьбе.
- На первом ноутбуке у git в терминале нет входа в GitHub и нет `gh`: пользователь отправляет ветку кнопкой синхронизации в VS Code. В браузере приложения вход в GitHub есть. Статус ветки можно посмотреть там, на странице коммитов: репозиторий закрыт, `git ls-remote` без входа не работает.

## Как устроено решение

- Данные: 5 камер, 20 минут, 2592×1944, cam_4 HEVC 20 кадр/с, остальные H.264 25 кадр/с. Метки времени в файлах сломаны: время только из номера кадра и `configs/clocks.yaml`. Часы камер расходятся до 0.8 с, сдвиги измерены по людям.
- Детекция: YOLO11m-seg (960, порог 0.1), BoT-SORT, OSNet-AIN через BoxMOT, 1 вектор в секунду, среднее камеры вычитается.
- Геометрия: модель объектива и камеры, подогнана к плану и уточнена по людям (`configs/cameras.yaml`, `src/mct/geometry.py`).
- Фильтр ложных и разрез кусков: `src/mct/tracklets.py`. Склейка: `src/mct/trinity.py`, порядок `sustained`, `brief`, `contacts`, `gaps`, `returns`, `finish`.
- Вывод: `scripts/link_tracks.py`, `render_mosaic.py`, `draw_gallery.py`, `check_robustness.py`, `make_showcase.py`, `make_report.py`, `demo_check.py`. Интерфейс: `app/demo.py`. Общие графики и таблицы: `src/mct/charts.py`, `summary.py`, `report.py`, `showcase.py`.

## Что сделано в последний день и почему

- **Правило рамок.** Два куска в непересекающихся рамках одного кадра не склеиваются.
- **Разрез при перескоке трекера** (`find_identity_jumps`). Половины куска разные, и у каждой рядом свой продолжатель, причём это заведомо разные люди. Порог половин от 0.4 до 0.6 даёт одно и то же.
- **Разрез при обмене номерами** (`find_tail_swaps`). Оба перекрёстных сходства от 0.5: иначе общий переход в другой свет на cam_2 давал ложное срабатывание.
- **Узкие послабления при сильном сходстве:** короткий контакт без края при R от 0.6, меньшая доля точек при R от 0.55, один объект на камере при R от 0.7.
- **Строже у двери.** Стык у двери на одной камере требует R от 0.2: блондинка вышла, человек в полосатом вошёл через 1.4 с.
- **Возврат до минуты** (`returns`). Сходство всего трека R от 0.6, человек успел бы дойти, нет заведомо другого человека с близким сходством. Пауза показывается как `blind_inferred`.
- **Окружение.** Были два пакета с модулем `cv2` (4.11 и 5.0), версия зависела от порядка установки. Теперь один `opencv-python==4.11.0.86`.
- **`make check`** сравнивает контрольные суммы (`render/full/built_from.json`), потому что git не хранит время файлов.

Толпа 17:45:25–47, ручная разметка 7 человек по одежде: соответствие 0.716 → 0.874, чистота 0.89 → 0.955. Разметка в `src/mct/fragment_truth.py`, пересчёт `scripts/eval_fragment.py`, раскадровки `scripts/draw_board.py`.

## Что пробовали и отбросили

- Выбирать между кандидатами только по внешности: отрывает верные куски, смаз и свет снижают сходство, 107–113 треков вместо улучшения.
- `gap_veto = 0.2` для всех разрывов: появляются сомнительные склейки через 3 с. Сейчас `gap_veto = 0.15`, он поставлен без явного ответа пользователя, откат одной строкой, ответа ждём.
- Отбрасывать дубли рамок: выбросило настоящего человека у пары в обнимку (cam_4, 48:46–48:53).
- Подозрения, которые не подтвердились: два человека 17:43 рядом со спорной связью оказались разными людьми с верными номерами; короткий трек с уверенностью 0.42 в 17:54:56 оказался настоящим человеком.
- Номера треков менялись при каждой правке: старые номера в истории переписки не совпадают с нынешними.

## Известные неточности

- **Детектор.** Нет детекции в 7–15% видимых точек; в выборке из 23 случаев настоящих пропусков около трети, в основном дальний конец коридора cam_5, 21–26 м. Остальное: дверная створка, которой нет на плане, ноги под камерой, ошибка положения.
- **Положение на плане.** Медиана расхождения камер 0.28–0.44 м; дальше 20 м у 10% точек больше 2.3 м. Рост на cam_4 занижен (1.64 м против 1.72–1.77 м).
- **Внешность.** Смаз и цветной свет снижают сходство; вернувшийся с R ниже 0.6 получит новый номер, доля таких случаев неизвестна.
- **Примеры ошибок (`KNOWN_ERRORS` в `src/mct/summary.py`, проверяются `make check`):** #39 с перескоком от толстовки к куртке; #40 как кусок человека, идущего #37; #26 двое в обнимку; #60 дубль мужчины в синем.
- **Отброшенное.** 18 уверенных кусков «вне пола» на cam_2: 17 далеко от настоящих треков, скорее всего отражения. Три куска «предмет» на cam_3 и один «не движется» на cam_4 (52:04) похожи на людей: не проверены и не исправлены.
