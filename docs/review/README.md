# Проверка четырёх отброшенных кусков, 7 ноября

Снимки извлечены последовательным чтением исходного видео по номерам кадров, с приведением к координатам восприятия 1296×972. На каждом листе четыре кадра одного исходного трека с окружением. Перемотка по временным меткам для этих записей неверна.

| Камера / исходный трек | Кадры | Причина фильтра | Результат осмотра | Возможный существующий ID |
|---|---|---|---|---|
| cam_3 / 192 | 5800–5860 | повторяющийся предмет | настоящий человек у дальней двери | #11 |
| cam_3 / 265 | 7648–7690 | повторяющийся предмет | настоящий человек у дальней двери | #25 |
| cam_3 / 402 | 9683–9705 | повторяющийся предмет | настоящий человек в коридоре | #33 |
| cam_4 / 241 | 16008–16290 | неподвижный низкий предмет | настоящая женщина, ноги перекрыты собеседницей | #57 |

Соответствия предполагаются по одновременному положению и внешности, не являются ручной эталонной разметкой. Косинус среднего необработанного OSNet-вектора с указанным треком на cam_5: 0.743, 0.530, 0.542 и 0.510 соответственно. Для cam_4 / 241 на той же камере сходство с #57 — 0.582. Эти величины не равны R после центрирования камер в алгоритме склейки.

Вывод: фильтр действительно теряет часть настоящих наблюдений. Доказательства дополнительного недосчёта людей по этим четырём случаям нет: есть вероятные продолжения на других камерах. Не восстанавливаем куски вручную по номерам. Следующее исправление должно проверять наблюдение по другим камерам и измерять ложные восстановления на экранах и отражениях.

Отдельно выполнен чистый пересчёт склейки на Windows: снова 75 треков, 229 отброшенных кусков, 35 спорных связей. CSV совпал после нормализации переводов строк; JSON различался только run_id/config_hash из-за CRLF в YAML. Хеширование настроек исправлено на LF.
